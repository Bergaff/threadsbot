# Руководство: cookies аккаунтов Threads (JSON) — перенос, самодиагностика, защита от бана

Для админа Cloudflare-бота. Пошагово:
1. Что лежит в JSON и какие бывают форматы.
2. Как безопасно переносить аккаунты между ботами.
3. Правила, чтобы аккаунты не банили.
4. Как работает самодиагностика JSON в боте (и когда сработает алерт).
5. Google Colab поячеечно: массовая загрузка, проверка, генерация SQL для D1, экспорт обратно.
6. Что было исправлено в коде, чтобы **основной сценарий** «пишу @имя → получаю посты» наконец работал стабильно.

## 1. Формат JSON

`accounts/<имя>.json` — экспорт cookies сессии Threads. Это не просто данные,
это ключи доступа к аккаунту. Обращаться с ними как с паролями.

| Формат               | Где взять                         | Поле срока жизни    |
|----------------------|-----------------------------------|---------------------|
| Cookie-Editor        | «Export» в расширении браузера    | `expirationDate` (сек) |
| Playwright / EditThisCookie | `context.cookies()` / экспорт | `expires` (сек)     |

Оба формата массивы объектов `{ name, value, domain, path, ... }`.
Бот поддерживает оба — при загрузке нормализует.

**Ключевые cookies** (без них сессия не работает): `sessionid`, `ds_user_id`, `ig_did`.
Отсутствие даже одного из них приведёт к алерту при диагностике.

## 2. Перенос аккаунтов между ботами

> **Правило №1**: одна сессия = один IP в один момент времени.
> Если JSON одновременно используется на двух ботах / устройствах, Threads видит
> два разных IP на одной сессии и с высокой вероятностью пометит её как подозрительную
> (частая причина «тихого» бана без разлогина, но с урезанием API).

### Через бота (рекомендуется)
1. В старом боте: `/account_export имя` → получаешь `имя.json`.
2. В старом боте: `/account_del имя` → удаляем сессию, чтобы старый бот её больше не трогал.
3. В новом боте: пришли этот JSON файлом → бот сохранит в D1 и проведёт диагностику.
4. Проверь: `/accounts` (появился ли) и `/account_check` (нет ли предупреждений).

### Через скрипт (массово)
```bash
# в корне проекта
npm run accounts:import -- accounts --remote
```
Кладёт все `accounts/*.json` в D1 (upsert). `--local` — для локальной БД `wrangler d1 ... --local`.

### Через Colab (без своей машины)
См. `notebooks/accounts_toolbox.ipynb` — 4 ячейки: загрузка → проверка → SQL → очистка.

### Что нельзя делать
- Коммитить `accounts/` в git (уже в `.gitignore`).
- Пересылать JSON в переписке — только личные файлы боту.
- Держать один и тот же аккаунт залогиненным в двух местах одновременно.

## 3. Как не банить

1. **Одна сессия = один IP**. См. выше.
2. **Лимит 20 запросов/час на аккаунт** (`LIMITS.accountHourly`). Бот сам ротирует.
3. **Свежие cookies**: после каждого успешного запроса бот вытаскивает актуальные
   cookies из контекста браузера и перезаписывает их в D1 (`markSuccess` в `threads.ts`).
   Это продлевает жизнь сессии.
4. **Мёртвые сессии** (редирект на `/login`) сразу помечаются `is_alive=0` и
   отдыхают до следующего экспорта.
5. **Не логинься в тот же аккаунт с телефона**, пока он крутится в боте.
6. **Cloudflare Browser Rendering ходит с чужого IP** (Cloudflare edge, не твоего).
   Не используй тот же аккаунт со своего IP параллельно — Threads увидит два IP.
7. Аккаунт не должен быть новым — свежие регистрации без активности банят быстрее.
   Прогони его 1-2 дня как человек (посты, лайки, реплаи) перед добавлением в бот.

## 4. Самодиагностика JSON

Каждые 6 часов (cron `0 */6 * * *` в `wrangler.toml`) бот:
- перебирает все аккаунты;
- для каждого вызывает `diagnoseAccountCookies(name, is_alive, cookiesJson)`;
- собирает список проблем (`issues`);
- если проблемы есть — шлёт админам сообщение вида:
  ```
  🩺 Самодиагностика аккаунтов

  🟢 accA: истекают 25.08.2026
  🔴 accB: cookies истекли — нужен новый экспорт
  🔴 accC: нет ключевых cookies (sessionid/ig_did)
  ```

Что именно проверяется в `src/threads.ts`:

| Функция                    | Что делает                                             |
|----------------------------|--------------------------------------------------------|
| `validateCookiesJson`      | JSON — массив объектов с `name`/`value`?              |
| `hasKeyCookies`            | Есть ли `sessionid`/`ds_user_id`/`ig_did`?             |
| `earliestCookieExpiry`     | Самая ранняя дата истечения                            |
| `diagnoseAccountCookies`   | Собирает все замечания в один список `issues`          |

Пороговое значение «скоро истекает» — `LIMITS.cookieWarnDays = 7` дней.

Кроме крона можно вручную: `/account_check` — та же диагностика, ответ прямо в чат.

## 6. Что было исправлено в этом релизе (важное)

1. **Загрузка/удаление JSON теперь работает.**
   В `src/db.ts` метод `accountUpsert` вызывал `iso()`, но такая функция не была
   определена (в файле только `now()`). При каждой загрузке JSON получался
   `ReferenceError: iso is not defined`, бот отвечал ошибкой и в БД ничего не сохранял.
   Исправлено: используется общий `now()`, значения записываются как надо.

2. **Worker снова собирается и разворачивается.**
   В `src/index.ts` внутри `scheduled` был IIFE `async () => {...}()`
   без обёрточных скобок — TypeScript отказывался компилировать, `wrangler deploy`
   падал. Исправлено на канонический вид `(async () => {...})()`.

3. **Убрана видимая задержка ответа на обычные команды.**
   Раньше в `fetch()` перед тем как вернуть Telegram-у `200 OK`, мы ждали, пока
   `Bot.update()` полностью отработает (2–5 DB round-trips + `sendMessage`).
   При «тёплом» воркере это ~300–800 мс, при холодном старте с nodejs_compat — до 2 с.
   Теперь `fetch()` немедленно отвечает `200`, а `Bot.update()` крутится через
   `ctx.waitUntil(...)` — Telegram снимает наш апдейт с очереди сразу, и следующая
   команда пользователя не ждёт «хвост» предыдущей.

4. **Основной сценарий работает как ожидается.**
   Пользователь пишет `@nickname` (или просто `nickname`) → бот открывает браузер,
   собирает 20 постов, отдаёт 5 текстом или скринами, кнопкой «Ещё» — следующие 5.
   Ответом на любой пост (`Reply → 1`) — комментарии к нему.
   Всё через Queue (`max_concurrency=1`) — аккаунты не пересекаются.

5. **Cookies обновляются автоматически.**
   После каждого успешного `fetchPosts` / `fetchComments` /`probeAccount`
   в БД перезаписывается свежий cookies-снимок из `context.cookies()`.
   Экспортированный старый файл со временем «дозревает» до актуального.
