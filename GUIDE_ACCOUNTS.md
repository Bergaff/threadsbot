# Руководство: cookies аккаунтов Threads (JSON), перенос и защита от бана

Это руководство для админа Cloudflare-бота. Здесь:
1. что лежит в JSON-файлах и какие бывают форматы;
2. как безопасно переносить аккаунты между ботами;
3. правила, чтобы аккаунты не банили;
4. как работает самодиагностика JSON в боте;
5. что делать по ячейкам в Google Colab, если что-то нельзя сделать через бота.

---

## 1. Что такое JSON аккаунта и какие бывают форматы

`accounts/<имя>.json` — это экспортированные cookies сессии Threads. Это
ключи доступа к аккаунту. Обращаться с ними как с паролями.

| Формат | Где взять | Поле срока жизни |
|---|---|---|
| Cookie-Editor | «Export» в расширении | `expirationDate` |
| Playwright `context.cookies()` | консоль/скрипт | `expires` |

Ключевые cookies: `sessionid`, `ds_user_id`, `ig_did`.

---

## 2. Перенос аккаунтов

**Одна сессия = один IP одновременно.** Не используй JSON в двух местах сразу.

### Через бота (рекомендуется)
1. Убедись, что аккаунт не занят в другом боте.
2. Пришли JSON файл боту → он сохранит в D1, продиагностирует.
3. `/accounts` — список, `/account_check` — проверка.

### Через скрипт
```bash
npm run accounts:import -- accounts --remote
```
Берёт `accounts/*.` → SQL → D1.

### Важно
Никогда не коммить `accounts/` в Git — уже в `.gitignore`.

---

## 3. Как не банить

1. Одна сессия = один IP.
2. Лимит 20 запросов/час на аккаунт.
3. Свежие cookies: после каждого запроса сохраняются в D1 (`markSuccess`).
4. Мёртвые сессии (редирект на `/login`) помечаются `is_alive=0`.
5. Не логинься в тот же аккаунт на телефоне, пока он в боте.
6. Cloudflare Browser Rendering — это другой IP, не используй аккаунт одновременно.

---

## 4. Самодиагностика

Cloudflare-версия:

| Команда | Действие |
|---|---|
| `/accounts` | список |
| `/account_check` | диагностика cookies |
| `/account_del имя` | удалить из D1 |
| `/account_export имя` | выгрузить JSON |
| Прислать JSON файл | сохранить в D1 |

Автоматически: каждые 6 часов (cron `0 */6 * * *`) — проверка + алерт админам.
